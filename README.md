# m125-pclms — open driver for HP LaserJet Pro MFP M125r on macOS

A small, fast CUPS driver (MIT license) for the **HP LaserJet Pro MFP M125r** and its
relatives, made for Macs where HP's own driver no longer installs, such as the MacBook Neo
running macOS 26 Tahoe on Apple Silicon.

* One C file (`src/rastertopclms.c`, about 1,100 lines) plus one PPD file. It uses only `libcups`
  and the C library, both built into macOS, so there are no extra libraries to install.
* The binary is about 40 KB. Converting a 600 dpi A4 page takes a few milliseconds.
* Compression runs on up to 4 threads. On Apple Silicon only the performance cores are counted
  (`hw.perflevel0.logicalcpu`), and the threads ask for the `USER_INITIATED` QoS class, so macOS
  schedules them on P-cores. Set `PCLMS_THREADS=1` to use one thread.

## Supported printers

The printer language is the one HP's Linux driver (HPLIP 3.26.6) calls `hbpl1`. In HPLIP it is
generated by HP's PCLm generator in "PCLm-S" mode: a PDF-1.7 file holding 8-bit gray image
strips, 64 lines each, compressed with RunLength, plus a `PCLmS-Job-Ticket` comment block on
each page.

| Family | Models | Status |
|---|---|---|
| LaserJet Pro MFP M125 | M125r, M125ra, M125a, M125s, M125nw, M125rnw, M125nr | target model (M125r, USB 03f0:222a) |
| LaserJet Pro MFP M126/M127/M128 | M126a/nw, M127fn/fw/fp/fs, M128fn/fw/fp | same language (in the PPD's product list) |
| LaserJet Pro MFP M129–M134 | M130, M132, M134 … | same language in HPLIP; untested |

## Install on macOS (MacBook Neo / any Apple Silicon or Intel Mac)

**The easy way:** download **Install HP M125r Driver.pkg** from this repository's *Releases*
page and double-click it. Step-by-step instructions for non-technical users (Russian and
English) are in [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md). The installer shows a welcome page,
the privacy notice and the Terms of Use (with an Agree step), and sets up the USB printer
itself. It also adds **Applications → HP M125r Driver → Set Up Printer / Uninstall**.

**From source, in Terminal:**

1. Copy this `driver` folder to the Mac.
2. Connect the printer by USB and switch it on.
3. In Terminal:
   ```bash
   cd ~/Downloads/driver          # wherever the folder is
   sudo ./macos/install.sh
   ```
   If the Xcode Command Line Tools are missing, a macOS window opens to install them
   (free, about 5 minutes). When it finishes, run the command again.
4. The script compiles a universal binary (arm64 + x86_64), signs it, installs it, runs a
   self-test and creates the queue `HP_LaserJet_Pro_MFP_M125r` on the USB port.
   If the printer was not detected, add it in **System Settings → Printers & Scanners → Add
   Printer**, select the M125r, and under **Use** choose **Select Software… →
   "HP LaserJet Pro MFP M125r, m125-pclms 1.0 (open driver)"**.

To uninstall: `sudo ./macos/uninstall.sh`. The install log is in `/Library/Logs/m125-pclms-install.log`.
Printing errors show up in `/var/log/cups/error_log` (run `cupsctl --debug-logging` for more detail).

### Apple code signing and notarization

* **Built on the Mac (`install.sh`)**: Apple Silicon runs only signed code, so the script signs
  the filter with an ad-hoc signature (`codesign -s -`). Files you compile yourself don't get
  the quarantine flag, so Gatekeeper doesn't block them. No Apple account is needed.
* **A `.pkg` for other people (`macos/build_pkg.sh`)**: to get through Gatekeeper without
  warnings, the package must be signed with *Developer ID* certificates and notarized by Apple.
  That needs an Apple Developer Program membership ($99/year). The script runs the whole chain
  when you give it the identities:
  ```bash
  xcrun notarytool store-credentials m125-notary --apple-id YOU@example.com --team-id TEAMID
  APP_IDENTITY="Developer ID Application: Name (TEAMID)" \
  PKG_IDENTITY="Developer ID Installer: Name (TEAMID)" \
  NOTARY_PROFILE=m125-notary ./macos/build_pkg.sh
  ```
  It signs the filter with the hardened runtime and a timestamp, runs `productbuild --sign`,
  `notarytool submit --wait` and `stapler staple`, and finally checks the result with `spctl --assess`.
  Without the identities it builds an unsigned `.pkg`. macOS will then ask for confirmation
  (Settings → Privacy & Security → Open Anyway).

## Install on Linux

```bash
make && sudo make install
sudo lpadmin -p M125r -E -v "$(lpinfo -v | awk '/usb:\/\/HP\/.*M125/ {print $2; exit}')" \
     -P "/usr/share/ppd/m125-pclms/HP LaserJet Pro MFP M125r PCLmS.gz"
```

## Testing

* `tests/verify_pclm.py OUT.pclm --raster IN.ras` is an independent checker. It checks every
  PDF xref offset, the job tickets, the RunLength end-of-data markers and the strip
  `/WhiteStrip` tags. It decodes every strip and compares the pixels with the CUPS raster
  that went in.
* `tests/vm/` holds the scripts and logs from the test run in an Ubuntu VM: real CUPS, the
  same PPD and filter, side-by-side comparison with HP's own `hpcups` 3.26.6 output for the
  M125r, plus speed and memory checks. See `docs/TEST_REPORT.md`.

**Caveat:** this has not been tested on a physical M125r yet. The output was checked
structurally and pixel by pixel against HP's driver, which is tested on real hardware, but
the first real print is the final test. If the printer shows an error or prints nothing,
collect `/var/log/cups/error_log` and the job file. `cupsfilter -p <ppd> file.pdf > job.pclm`
produces one.

## How it works

```
PDF from app ─► macOS cgpdftoraster ─► CUPS raster (8-bit gray, 600 dpi) ─► rastertopclms ─► USB
                                                                        │
             64-line strips ─► RunLength (threads) ─► PCLm-S page objects in order
```

Page geometry follows HP's PCLm-S output exactly. The strip width is the full media width.
The printable area (14 pt margins) is shifted right by the left margin. The top margin is
sent as white strips, every strip has 64 lines, and the PDF objects, xref layout and job
ticket keys appear in the same order HP uses.

## Building the installer (GitHub Actions)

`.github/workflows/macos.yml` runs on GitHub's Apple Silicon Macs on every push. It:
1. builds the universal filter and the helper apps and signs them ad-hoc (`macos/build_pkg.sh`);
2. installs the `.pkg` on clean **macOS 15** and **macOS 26** machines;
3. runs `macos/ci/smoke_test.sh`, which checks file ownership and signatures, prints through
   macOS's own PDF→raster pipeline and through a real `cupsd` queue, checks every option's job
   ticket, measures speed with 1/2/4/auto threads, and checks that uninstall leaves nothing behind;
4. on a tag such as `v1.0.0`, publishes the `.pkg` on the Releases page.
